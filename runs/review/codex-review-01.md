## Implemented crates: safety and contract assessment

- **Storage positive evidence:** `container/write.rs:225` implements append-pages → sync → inactive superblock → sync → publish; failed sync/superblock writes poison the container. `gc/compact.rs:88` publishes the renamed file and poisons on directory-sync failure. Btree reads bound depth/check child levels; overflow walking is length-bounded. Existing fault/property tests passed. These checks do not cover the export name-ownership race or checksummed pathological header fields above.
- **Core positive evidence:** commit rereads the current branch head under the writer, applies the overlay there, checks branch generation, and releases locks after durability (`commit.rs:131`). RC snapshots refresh at statement start; RR retains its snapshot. Savepoint rollback undoes overlay changes and releases subtransaction grants. No claim of complete lock/deadlock correctness is warranted from the current tests; repeated lock outcomes are demonstrably wrong.
- **SSI is not connected.** `ssi.rs:526` reports active and has tracker-only tests, but `txn_kv.rs:103`–`:137` never calls `on_read/on_write`; commit/rollback paths never call `on_finish`. `ssi.rs:400` accepts an unregistered transaction's commit. Serializable therefore still has the documented RR/write-skew gap despite an implemented tracker. `docs/compatibility/KNOWN_GAPS.md`, required by architecture §7, is absent. Do not advertise the tracker as end-to-end SSI or infer compatibility from its isolated tests. A later integration owner must wire all reads/writes, empty commits and rollback/drop, and test two-session write skew through Engine.
- **Catalog:** versioned decoding rejects invalid JSON/unknown versions/key-OID mismatches, and snapshot building checks several references/name collisions. It does not establish semantic validity of all decoded models; the domain-cycle abort is one concrete hole. DDL writes through to the transaction overlay before follow-ups: session error/savepoint cleanup is essential, not optional. Stats producers (`vrel/stats.rs:1`, `:77`) deliberately synthesize zero counters. This is disclosed in the crate contract, but conflicts with architecture §0's blanket ban on fake results; resolve with an explicit compatibility amendment or return leased 0A000. It is not real statistics collection.
- **Types/panic audit:** no production `panic!`, `todo!` or `unimplemented!` found in the focused implemented-crate scan. The direct `parts.pop().unwrap()` at `types/names.rs:437` follows a mandatory push and is not a demonstrated user-input panic. Most other matches were tests/docs or parser methods named `expect`. The confirmed failures instead use recursion/arithmetic. Tuple decoding has bounded counts and depth, unlike unrestricted JSONB consumers. The byte-order/property tests are valuable but do not substitute for SQL/oracle coverage.
- **Contract drift:** many catalog/type layout changes have explicit amendments; they should not be flagged merely for differing from the architecture sketch. Conversely, “PROPOSED” executor requirements and error-context amendments are not ratified guarantees. No exhaustive semantic equivalence audit of all type functions, ACL operations or catalog virtual relations was performed.

## Harness integrity and coverage limits

The comparator preserves NULL/empty distinction, row multiplicity, column OIDs/typmods/origin, command tags, transaction status and SQLSTATE. Missing/stale reference files are BLOCKED rather than PASS. The public corpus recorder verifies live oracle identity and runs twice. These are good safeguards, subject to tickets 6–7.

Additional limits:

- Opt-in timestamp normalization (`compare/normalize.py:221`) masks **every** non-null date/time column in a step, including deterministic expressions beside `now()`. Scope masks to the nondeterministic expression/column and add mutants; otherwise incorrect date arithmetic can pass. Similar provenance concerns apply to PID/XID/UUID masks.
- Recorder determinism compares canonical JSON directly (`oracle/recorder.py:238`), before applying the comparator's unordered-row semantics. Legitimate row reordering can be rejected as nondeterminism. This loses coverage rather than causing a PASS; preserve the denominator and report the loss.
- Lease validator currently finds `CLI-26 -> CLI-27 -> CLI-26` (`contracts/leases/pgarbor-cli.json:891`, `:923`); marker mismatches at `harness/tests/test_fac_07.py:201`, `:270`; and an “unleased stub” from the **test** example at `common/src/error.rs:289`. Independent small tasks: break the CLI lease cycle, and teach inventory to distinguish executable stubs from test fixtures without suppressing real production markers. Do not remove tests/markers just to satisfy validation.
- The tests exercise components and mocks. No runnable psql slice was demonstrated, and offline pytest skips live-oracle tests. Expected-output count is not a count of engine compatibility passes.

## Fastest credible psql vertical slice

1. **Assemble one explicit critical path.** Current API entry points still return leased 0A000 (`pgarbor/src/simple_query.rs:46`, `run_stmt.rs:68`, `ctx_build.rs:56`, `txn_block.rs:97`). Completing wire/CLI surfaces alone cannot execute SQL. Integrate create/open → bootstrap postgres/public → connect → simple Query → parse/bind → Result/Values/SeqScan/Filter/Project → transaction commit → RowDescription/DataRow/CommandComplete/ReadyForQuery. Then CREATE TABLE, INSERT, SELECT ordered rows, rollback, close/reopen, and one primary-key violation. Use real psql `-X`/`ON_ERROR_STOP`, plus `\dt` only after catalog joins/helpers work. Defer optimizer breadth, hash/merge joins, windows, FFI and prepared-plan heuristics until this gate passes.
2. **Protect statement/session boundaries.** API contract `pgarbor.md:45`–`:64` correctly requires whole-string parsing, per-statement binding, one implicit transaction across a multi-statement Query, failed-block status and transactional GUCs. Give txn_block one owner and run_stmt one owner against shared fixtures. Test `CREATE; INSERT; SELECT`, `INSERT; error; INSERT` rollback, `BEGIN; error; COMMIT` → ROLLBACK, and rollback-to-savepoint restoring catalog/GUC state. A low-level CRUD success does not cover these boundaries.
3. **Make DDL retry safe.** The catalog version-lock protocol is sound only if the API retries before side effects, rebuilds catalog/bind/plan state and retains the surrounding transaction. `exec/ddl_driver.rs:40` locks before catalog mutation; preserve that ordering. Exercise two RC sessions creating the same name and RR rejection. Fix repeated lock outcomes first. Test follow-up failure plus ROLLBACK TO restoring the session catalog cache.
4. **Resolve incompatible promises before broad plans.** `pgarbor-exec-02-upstream-requirements.md` is PROPOSED: equal hash-key types, EPQ input shape, stored-expression rebinding, virtual attnums and session retry cannot be assumed by independent agents. Ratify shared row/slot/type invariants and run one end-to-end test for each before enabling that path. Until then use the contract's correct seq-scan/nested-loop fallback.
5. **Reject semantic no-ops.** `contracts/crates/pgarbor-exec.md:100` promises deferred constraints checked early and SET CONSTRAINTS ignored; `sql/ir/stmt.rs:774` and `exec/execute.rs:87` provide a generic successful Noop route. This contradicts the no-silent-stub rule. Return leased 0A000 for unsupported deferred semantics. Likewise, storing RLS flags without execution enforcement must not authorize unfiltered non-owner reads. Add negative acceptance gates before enabling such syntax.
6. **Close error/wire contracts only as needed.** `pgarbor-types-02-error-context.md` remains PROPOSED; common PgError has no CONTEXT, while `compare/typed.py:184` compares it when `compare_message` is true (the default). JSON/COPY error parity will fail for this structural reason. Ratify/add the field and propagate wire W; do not weaken the comparator. Start with simple Query; add Parse/Bind/Describe/Execute/Sync once transaction ownership and result metadata work, not as a prerequisite for the first psql gate.
