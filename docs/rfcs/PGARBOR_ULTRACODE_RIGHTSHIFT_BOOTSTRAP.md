# Ultracode invocation — PGArbor RightShift factory bootstrap

Read `PGARBOR_RFC_001.md`, `PGARBOR_RFC_002_AUTONOMOUS_VERIFICATION.md`, `PGARBOR_RFC_003_RIGHTSHIFT.md`, and `PGARBOR_RIGHTSHIFT_TASK_GRAPH.json` in full before planning work. RFC 003 supersedes RFC 002's per-worker test and verification gates; the correctness and oracle requirements of RFC 001/002 are unchanged.

**MISSION:** Build an autonomous, greenfield Rust database with native single-file CoW branching, aiming at full PostgreSQL 18 behavioral compatibility. Implement the RightShift engineering protocol: lock contracts, dispatch many non-overlapping speculative implementation workers, collect patches, assemble a big epoch, run an expensive trusted verification campaign centrally, classify/minimize failures, then generate the next epoch's repair DAG. The engine itself and harness must both become real executable software; no fake green tests, empty crates, silently unsupported SQL, or documentation-only completion. Keep making progress while budget and resources permit. Do not claim results that have not been tested.

**FIRST ACTION — name:** Current selected name is `PGArbor` (`pgarbor` CLI/crate prefix, `.pga` database file, `.pgabranch` optional branch handle). Check project namespace availability (GitHub, crates.io, trademark and common software collisions). If current planned name collides, choose an unoccupied alternative *before any crates/repos/code are created*, regenerate all files and contracts in a single naming transaction. Do not let a provisional collided name enter committed code.

**PHASE A — contracts:** Load/validate DAG IDs and cycles. Freeze source ownership and Rust APIs, branch/txn/storage/protocol contracts, error/OID semantics and test oracle schema. Use strong model for architectural decisions; use cheap model for well-scoped source reading and code implementation. Need no per-worker builds/tests.

**PHASE B — speculative wave:** Transform high-level manifest tasks into bounded leaf tasks with disjoint writable paths; lease to workers in independent worktrees with pinned API contract context. Implement aggressively. Each worker submits code, artifacts, reference behavior provenance, unresolved assumptions and unexecuted proposed tests. Do not compile or run entire suites in each worker; avoid each worker starting Docker or PostgreSQL. Shared traits change only via dedicated amendment tasks.

**PHASE C — integrate:** Collect patches deterministically; merge staged epoch respecting dependencies. Cluster contract collisions. Run a single central workspace build once a coherent wave is assembled; coordinate limited repairs for compilation if needed. Preserve failed patches and evidence; never overwrite or force-push another worker's work.

**PHASE D — verify:** Run central fault-model storage/branch suite plus pinned PG18 differential tests, official regressions and isolation tests as supported, wire transcripts, and unmodified SQLx/Drizzle/Prisma fixtures. Report exact SHA, environment, seeds, PASS/FAIL/BLOCKED/UNRUN and resource costs. Agents cannot modify trusted oracle, denominator, expected output, or acceptance rules in feature patches. Critical data corruption has absolute priority.

**PHASE E — repeat:** Minimize differences, group root causes, generate graph-linked repair tickets, score by dependencies unlocked and criticality. Launch next speculative wave. Reverify only at wave boundaries (except necessary centralized compile repair). Escalate genuine architecture blockers to a strong reasoner instead of infinite retries. No artificial final success criterion until earned against the pinned feature inventory.

**OPERATING PRINCIPLES:** Massive implementation batches; front-loaded interface discipline; expensive verification concentrated at RightShift epoch boundaries; no verifier gaming; avoid unnecessary resource thrash; preserve durable state and crash recovery; no feature secretly accepted without correct semantics; portability and native branching are foundational. Progress metric: newly verified PG behaviors and storage invariants per compute dollar, not agent count or code volume.

**OUTPUTS:** Real repository code, versioned contract ledger, task/agent state, machine-readable evidence reports, replayable discrepancy fixtures, evolving DAG, completed north-star database demo. Produce a concise run report with completed/blocked/untested counts and exact next actions.
