# pgarbor-catalog — crate contract v1

Status: RATIFIED skeleton (contract freeze). Leases: `contracts/leases/pgarbor-catalog.json`
(CAT-01..CAT-49). Seed tasks: CAT-01..CAT-12. Amendments: `pgarbor-catalog-01-space3-subtag`,
`-02-oid-allocation`, `-03-builtin-proc-columns`, `-04-sql-expression-rewriter`, `-05-space1-layout`.
Depends on: pgarbor-common, pgarbor-types (never on storage, core or sql).

## Purpose

The PostgreSQL 18-compatible SYSTEM CATALOG of one branch:

1. an object model (schemas, relations/columns, indexes, constraints, sequences, enums/domains/composites,
   functions, roles, databases, comments, ACLs) persisted as versioned JSON rows through the
   `KvRead`/`KvWrite` traits (it never sees pages, branches or transactions);
2. immutable, cheaply clonable `CatalogSnapshot`s with PG name resolution (`search_path`, visibility,
   reg* lookup) and an implementation of `pgarbor_types::TypeEnv`;
3. the DDL writer `CatalogTxn` (create/alter/drop of every object kind, automatic PG-exact names,
   ownership and privilege checks, dependency-aware DROP with exact 2BP01 errors and CASCADE notices);
4. VIRTUAL `pg_catalog` and `information_schema` relations (213 relations with the exact PG 18.6 column
   lists) generated from the snapshot, the compiled-in PG 18.6 tables and the session;
5. catalog-backed SQL functions (`pg_get_expr`, `pg_get_constraintdef`, `has_table_privilege`, ...).

## Data formats (byte-exact, frozen at v1)

### Space 1 (`00 00 00 01`) — catalog rows
```
object:       [00 00 00 01] [kind u8] [oid u32 BE]                                  (9 bytes)
description:  [00 00 00 01] [b'D']    [classoid u32 BE] [objoid u32 BE] [objsubid u32 BE ^ 0x8000_0000]  (17 bytes)
```
Kind bytes: `n` namespace, `r` relation (tables, views, matviews, composite types), `i` index, `S` sequence,
`t` type (enum/domain), `c` constraint, `f` function, `a` role, `m` role membership, `d` database, `D`
description. Value: `[0x01 FORMAT_V1]` + `serde_json` of the model struct (a description is a JSON string).
Unknown leading byte -> `XX001 unsupported catalog row format version N` (fail closed). Evolution rule:
new struct fields must be `#[serde(default)]`; renames/removals need a new format byte and a migration.
Builtin objects (pg_catalog, information_schema, pg_toast, predefined roles, templates, collations, system
relations with exact PG 18.6 OIDs) are compiled in (`builtin/*`, generated by `gen/gen_builtin.py` from
`contracts/reference/pg18`). Only `public` (2200), role `postgres` (10) and database `postgres` (5) are
written at bootstrap so they can be altered or dropped like any user object.

### Space 3 (`00 00 00 03`) — only the `cat:` sub-prefix belongs to the catalog (amendment 01)
`cat:version` = counter u64 BE ‖ stamp u64 BE; `cat:bootstrap` = u32 BE (1); `cat:next_oid` = u32 BE
(standalone only). Relation DATA keys (`[relid][rowid]`) and sequence state (space 2) are NOT touched by
this crate; the executor receives `FollowUp`s for them.

## Key invariants

1. **One OID space per branch.** User OIDs start at 16384 and come from the `OidSource` half of the `CatalogStore`
   (amendment 02). OIDs are not expected to equal PG's (PG burns OIDs on toast tables and RI triggers); tests never
   compare user OIDs to the oracle. OIDs embedded in values (rowtype, array type, attrdef, enum label) are
   unique in the same space (`CatalogData::max_oid` feeds the seed).
2. **Snapshot = content identity.** Every catalog-writing statement bumps `cat:version` (counter, random
   stamp) in the same transaction as the rows. The pair identifies catalog content across branches, resets
   and rollbacks, so `CatalogCache` can share snapshots between branches forked at the same state; an
   uncommitted transaction's snapshot has a pair nobody else sees.
3. **Dependencies are derived, never stored.** `depend::DepGraph::build` computes every `pg_depend` edge
   from the model (edge table in `depend.rs`, verified against a real PG dump); `pg_depend` is generated
   from the same function. Consequently a model field that is inconsistent (e.g. `Sequence::owned_by`
   without the column) is a bug, not a stale row.
4. **Columns are never renumbered.** `Relation::columns[i].attnum == i + 1`; DROP COLUMN keeps the slot
   (`........pg.dropped.N........`, type oid 0) so stored tuples (positional) keep decoding.
5. **Expressions are canonical text.** `StoredExpr.sql` is exactly what `pg_get_expr` prints
   (`nextval('t_id_seq'::regclass)`, `(c > 0)`); the binder (pgarbor-sql) produces it. A rename that
   changes the text goes through `ExprRewriter` (amendment 04). Known divergence: a `regclass` literal
   inside a default is fixed at creation time (PG re-prints it per search_path).
6. **No panics, no silent stubs.** Unimplemented behavior is `Err(PgError::unimplemented("CAT-NN", ..))`.
7. **Statement atomicity is the transaction layer's job.** `CatalogTxn` writes through; on `Err` the
   caller rolls back to its statement savepoint.

## Transactions, concurrency and invalidation (protocol)

Statement start (any statement): `snap = cache.snapshot(&txn_kv)`; compare `snap.ptr_eq(session.snap)`; if
different rebuild `CatalogEnv` (re-resolve `search_path` when `invalidation::diff` reports `schemas`) and
revalidate prepared plans with `invalidation::plan_is_stale(&PlanDeps, &Invalidation, old, new)`
(PG `cached plan must not change result type` 0A000 is the session layer's).

DDL statement:
1. take the catalog write lock: `txn.lock_key(&ddl_lock_key(), ForUpdate, Block)` BEFORE the first catalog
   write. DDL is therefore serialized per branch (PG locks per object; documented difference: queued DDL
   and possible `40P01` where PG would not report one). Without the lock two sessions creating `public.t`
   concurrently get different OIDs and both commit -> duplicate names -> `XX001` at the next snapshot build.
2. outcome `Changed`: READ COMMITTED -> `begin_statement`, reload the snapshot, re-bind and retry; REPEATABLE
   READ/SERIALIZABLE -> `40001`. `CatalogTxn::begin` re-checks `read_version == snapshot.version()` and raises
   `40001 could not serialize access due to concurrent catalog change` otherwise.
3. `CatalogTxn::begin(&mut store, &env)` where `store: &mut dyn CatalogStore` is the `pgarbor` crate's wrapper around the `TxnKv` that also implements `OidSource` through `alloc::next_oid(txn, &oid_seed)`, run operations, `finish_statement(stamp)`
   with `stamp = random_u64() ^ txn_id` (must be unique per call).
4. perform `DdlResult::outcome.follow_ups` in order (`BuildIndex`, `Validate*`, `RewriteTable`,
   `DropRelationData`, `CreateSequenceState`, `DropSequenceState`, `RestartSequence`, `PopulateMatView`,
   `RequireEmptyTable`), forward `notices`, swap the session snapshot to `DdlResult::snapshot`.
5. rollback / ROLLBACK TO SAVEPOINT drop the overlay including the catalog rows and the version bump; the
   session's cached snapshot is then re-derived by step "statement start" (version differs -> reload).
DDL is transactional exactly like data (it lives in the same tree): CREATE TABLE in an aborted transaction
leaves nothing. Branches fork the catalog for free (copy-on-write) and inherit `cat:version`.

## Virtual relations

`Relation::is_virtual()` (OID < 16384) relations have no row storage. The binder resolves them like tables
(`builtin::builtin_relation`); the executor calls `vrel::scan(&ScanContext{env, session, io_config}, oid,
&ScanRequest{eq filters})` and re-applies the WHERE clause. Row shapes: `vrel/mod.rs` (Datum mapping table).
Classification of all 213 relations (checked by `gen/classify_vrel.py`):
- real producers (CAT-28..CAT-36, CAT-38..CAT-44): pg_namespace, pg_class, pg_attribute, pg_attrdef,
  pg_type, pg_enum, pg_range, pg_index, pg_constraint, pg_depend, pg_description, pg_shdescription,
  pg_shdepend, pg_proc, pg_aggregate, pg_operator, pg_cast, pg_language, pg_authid, pg_roles, pg_shadow,
  pg_user, pg_group, pg_auth_members, pg_database, pg_db_role_setting, pg_tablespace, pg_collation, pg_am,
  pg_opclass, pg_opfamily, pg_extension, pg_available_extensions(+_versions), pg_inherits, pg_sequence,
  pg_rewrite, pg_tables, pg_views, pg_matviews, pg_indexes, pg_sequences, pg_settings, pg_stat_activity,
  pg_locks, pg_prepared_statements, pg_cursors, pg_stat_ssl, pg_stat_gssapi, 18 per-relation pg_stat*/
  pg_statio* views (zero counters), and 48 information_schema views;
- correctly EMPTY (`vrel/empty.rs`, 69 relations, each with a justification: triggers, policies, foreign
  data, publications, large objects, security labels, planner statistics, replication, progress views, ...);
- UNSUPPORTED (`vrel/unsupported.rs`, 29 relations): scanning raises `0A000` instead of lying.

## Error conventions

All user-facing errors/notices are built by `crate::errors` with PG 18.6 wording verified against the
oracle (SQLSTATE always; message text deterministic). Catalog corruption is `XX001`
(`PgError::corruption`). NOTICEs are `PgError`s with severity Notice collected in `DdlOutcome::notices`.

## How downstream crates use it

- **pgarbor-sql (binder):** `CatalogEnv` for every name (`lookup_class`, `resolve_relation`,
  `function_candidates`, `lookup_type` + `pgarbor_types::names` for SQL type spellings); builds the
  `ddl::spec` structs (resolving names to OIDs, deparsing expressions into `StoredExpr`, filling
  `depends_on`); implements `ExprRewriter` (amendment 04).
- **pgarbor-plan:** reads `Relation`/`Index`/`Constraint` (index choice, FK checks, column list) and sees
  `is_virtual()` relations as scan nodes of `vrel::scan`.
- **pgarbor-exec:** runs DDL (`CatalogTxn` protocol above), executes `FollowUp`s, scans virtual relations,
  and routes `SessionContext::call_external` to `sysfuncs::handles/call/call_set` first (the `OidSource`
  over `pgarbor_core::alloc` is supplied by the `pgarbor` crate).
- **pgarbor (embedded API):** owns the `CatalogCache`, `SessionInfo` implementation (settings from GUCs,
  activity/locks from `pgarbor_core::diag`, sequence state from `pgarbor_core::sequence::store`), calls
  `persist::bootstrap` when creating `main`, supplies `stamp` and `OidSource`.
- **pgarbor-cli / branches:** `diff::diff_schemas(&a, &b)` for `branch diff`.

## Documented divergences and known gaps (also in docs/compatibility/KNOWN_GAPS.md when created)

- no TOAST tables (`reltoastrelid` 0); `relfrozenxid`/`relminmxid` are constants; `relpages`/`reltuples`
  are static (-1 / 0);
- system INDEXES appear in `pg_class` but not in `pg_index`/`pg_indexes`/`pg_stat_*_indexes`; `pg_amop`,
  `pg_amproc`, `pg_conversion`, `pg_init_privs`, `pg_ts_*`, timezone views are UNSUPPORTED (0A000);
- `pg_node_tree` columns hold deparsed expression text; `pg_get_expr` returns its input; `pg_rewrite.ev_action`
  is the view query text; rule OIDs equal view OIDs;
- some `pg_proc`/`pg_type`/`pg_operator`/`pg_aggregate` columns are not recorded in `pgarbor-types` and are
  0/NULL/defaults (amendment 03);
- `inet` / `pg_lsn` / `xid8` have no `Datum` variant: `pg_stat_activity.client_addr` is NULL;
- DDL is serialized per branch; temporary tables/schemas, inheritance, partitioning, triggers, rules,
  policies, event triggers, FDWs, publications, extended statistics, text search objects, ALTER DEFAULT
  PRIVILEGES, GRANT ON PARAMETER, CREATE DATABASE, EXCLUDE constraints and non-btree index methods are
  unsupported (0A000 at DDL or absent catalog rows);
- statistics views report zero counters (no collection); `relation_size` needs `SessionInfo`;
- a comment removal on a builtin object re-exposes the compiled-in description.

## Non-goals

SQL parsing/binding/deparsing (pgarbor-sql), data storage (core/storage), sequence state (core),
constraint ENFORCEMENT and index maintenance (exec), privilege checks on data access (exec calls
`acl`/`sysfuncs::privs`), localized messages.
